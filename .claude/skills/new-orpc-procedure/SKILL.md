# New oRPC procedure

Procedures live in the service that owns the feature, under `packages/services/<name>/src/`. The layers are described in `.claude/rules/service-architecture.md`, which you must follow.

- **Routes** (`routes/`) build procedures on the service's local `procedure` (`routes/procedure.ts`). That file extends the shared `publicProcedure` from `@trips-app/rpc`, and it is the place for the service's middleware and error definitions. Routes validate input, call one service, and map errors.
- **Services** (`services/`) export `createXService(db)`. They hold the business logic and call repositories.
- **Repositories** (`repository/`) are the only layer that uses `@trips-app/db`.
- `packages/rpc` mounts every service's `routes` under `appRouter`. The mounting file `packages/rpc/src/routers/services.ts` is generated by `bun scripts/services.ts sync`. Do not edit it by hand.
- The server serves `appRouter` over RPC and OpenAPI (`apps/server/src/index.ts`). The web app gets a typed client from `apps/web/src/utils/orpc.ts`.

## Steps

1. **Add the schema.** In `schemas/validation/index.ts`, define the input with zod. Every input is validated; never trust the client.

   ```ts
   import { z } from "zod/v4";

   export const getTripInput = z.object({
     id: z.uuid(),
   });
   ```

2. **Add the data access.** In `repository/index.ts`, write the query. Filter every tenant-owned query by tenant ID (DAT-01). The `ServiceDatabase` type is re-exported there from `@trips-app/db`. The schema is still empty, so adapt the query once real tables exist (`import { schema } from "@trips-app/db"`).

3. **Add the service function.** In `services/index.ts`, put the business logic in the factory:

   ```ts
   export function createTripsService(db: ServiceDatabase) {
     return {
       async getTrip(id: string) {
         // call a repository function here; enforce plan and permission rules here
       },
     };
   }
   ```

4. **Add the route.** In `routes/index.ts`, replace the empty router with the procedure. The route reads `context.db` and passes it to the factory. It never imports a repository.

   ```ts
   import { procedure } from "./procedure";
   import { getTripInput } from "../schemas/validation";
   import { createTripsService } from "../services";

   export const routes = {
     getTrip: procedure
       .input(getTripInput)
       .handler(({ input, context }) => createTripsService(context.db).getTrip(input.id)),
   };
   ```

   Expected failures throw `ORPCError` with a code. Database errors are never returned to the client.

5. **Wire it.** Run `bun scripts/services.ts sync`, then `bun run services:check`. The procedure appears in the client as `client.<service>.getTrip`, where `<service>` is the camelCase service name (for example `client.trips.getTrip`).

6. **Do not invent auth.** There is no `protectedProcedure` yet. If the procedure reads or writes user data, stop and ask the user how authentication should be wired. Do not add ad-hoc session checks inside the handler.

7. **Type-check.** From the repo root run `bun run check-types`. The web client's `AppRouterClient` type is derived from `appRouter`, so a type error here means the client is broken too.

8. **Call it from the web app.** Use the exported `client` from `apps/web/src/utils/orpc.ts`. Its types come from the router, so do not hand-write request or response types.

   ```ts
   import { client } from "@/utils/orpc";

   const trip = await client.trips.getTrip({ id });
   ```

9. **Test.** Follow `.claude/rules/api-endpoint-testing.md`. Add a unit test for the input schema in `packages/services/<name>/test/`, and an e2e test in `apps/server/test/e2e/` for the HTTP contract, including the auth and validation cases. If the procedure is meant to be public, add it to `INTENTIONALLY_PUBLIC` in `packages/api/src/testing/procedure-catalog.ts` with a reason.
10. **Verify.** Run `bun run services:check`, `bun run check-types`, `bun run lint`, and `bun run test`.

## Checklist

- [ ] Input validated by a zod schema in `schemas/validation`
- [ ] Data access only in `repository`, with a tenant filter on every query
- [ ] Route only calls the service factory; it does not import a repository
- [ ] `bun scripts/services.ts sync` run; `packages/rpc/src/routers/services.ts` not edited by hand
- [ ] Expected errors thrown as `ORPCError`, no raw DB errors returned
- [ ] No auth shortcut added without confirming with the user
- [ ] `services:check`, `check-types` and `lint` pass
- [ ] Web call uses the typed `client`, no hand-written types
